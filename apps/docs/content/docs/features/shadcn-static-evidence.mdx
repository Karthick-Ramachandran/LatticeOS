<Callout title="Implemented" type="info">
  LatticeOS can connect a supported `components.json` UI alias to indexed React components. Storybook
  manifest evidence is still separate Phase 1 work.
</Callout>

shadcn is optional. A repository without a supported configuration receives the normal React and
Tailwind Reuse result. LatticeOS reads `components.json` as JSON text and never calls a registry,
starts shadcn, imports consumer code, or executes configuration.

## What it records

LatticeOS accepts a supported shadcn configuration with a string `aliases.ui` value. It resolves that
value as either:

- a repository-relative UI directory, such as `src/components/ui`;
- an exact direct-root TypeScript path alias, such as `@fixture/ui`;
- a direct-root TypeScript path alias with one wildcard, such as `@/*` to `src/*`.

When an indexed React component lives under a resolved UI directory, the Reuse index adds a `registry`
record to that component. The record points back to the `aliases.ui` entry in `components.json`.

This is corroborating evidence. The configuration proves that the source tree is the configured shadcn
UI location. It does not prove that a component came from a particular registry, is unchanged, or fits
every task.

```ts title="Direct static adapter input"
import { analyzeShadcn } from "@latticeos/adapter-shadcn";

const result = analyzeShadcn({
  configs: [{ path: "components.json", content: configText }],
  components: reactAnalysis.components,
  compiler: {
    baseUrl: ".",
    paths: { "@fixture/ui": ["packages/ui/src/index.ts"] },
  },
});
```

`analyzeProject` runs the bounded analyzer bridge after React analysis, so CLI search, inspect, and
context results receive the added evidence automatically.

## Unsupported forms and bounds

Package-local tsconfig files, tsconfig `extends`, multi-step alias chains, multiple wildcard patterns,
and configurations with no usable `aliases.ui` value do not map components. They produce a bounded
diagnostic and leave React evidence usable.

The analyzer reads at most 20 `components.json` files and 1 MiB of total config text by default. A
single file still follows the repository's 1 MiB file bound. The limits have hard caps and no adapter
filesystem access.

The named `fixtures/next-workspace` fixture proves a real `components.json`, its exact TypeScript path
alias, and six indexed UI components. The direct adapter golden also covers repository-relative and
single-wildcard aliases. Absent, malformed, and unresolved inputs leave the Reuse index valid without
copying config contents into output.

```bash
pnpm --filter @latticeos/adapter-shadcn test
pnpm --filter @latticeos/analyzer test
```
