## Outcome

In a React, Next.js, TypeScript, and Tailwind repository, an agent can answer:

- Which exported component already fits this task?
- What props and visible variants does source actually define?
- Where is that component used, and what is composed around it?
- Do Storybook or shadcn add concrete examples?
- Which exact Tailwind bundles repeat often enough to deserve attention?

LatticeOS returns a small ranked result instead of dumping the full component inventory into the
agent context.

## Evidence structure

Each recommendation has reason codes that resolve to evidence records.

| Field | Meaning |
| --- | --- |
| `kind` | Export, prop, import, usage, story, registry, token, or repeated class evidence |
| `location` | Repository-relative source path and position |
| `method` | AST, type checker, static config, CSS, or manifest extraction |
| `classification` | Exact fact, corroborating example, or heuristic |
| `fingerprint` | Stable source fingerprint used to detect stale evidence |
| `limitations` | Dynamic or unsupported syntax that analysis could not prove |

A score explains ranking. It does not claim that two components have the same product meaning.

See the [implemented Reuse index reference](/docs/reference/reuse-index) for component identity,
validation, serialization, search, ambiguity, and context budget behavior.

See [safe project discovery](/docs/features/project-discovery) for the implemented repository read
boundary, exclusions, scan limits, workspace forms, tool markers, and incomplete-scan behavior.

See [React component analysis](/docs/features/react-component-analysis) for the implemented static
component, prop, import, JSX, and usage extractor and its supported syntax forms.

See [Tailwind static analysis](/docs/features/tailwind-static-analysis) for the implemented token and
repeated-bundle extractor, its exact static forms, and its dynamic-expression limits.

See [Reuse index assembly](/docs/features/reuse-index-assembly) for the implemented read-only
analysis entry point, deterministic index validation, truncation behavior, and its named golden.

## Planned workflow

```bash title="Find reusable UI"
lattice search "team settings"
lattice inspect SettingsSection
lattice context "build a team settings page" --json
```

The human output is for quick reading. JSON carries an explicit schema version and the full evidence
links needed by an agent or test.

## Limits

- Phase 1 uses static evidence. It does not execute consumer source or configuration.
- Dynamic Tailwind classes may be reported as unsupported.
- Repeated classes are informational. LatticeOS does not create a component from them.
- Storybook and shadcn are optional.
- Figma, semantic rules, Doctor, browser comparison, and repair loops are later phases.

## Proof required before Phase 2

The packed CLI must run in a realistic Next.js fixture. Golden tests must match component, prop,
usage, alias, workspace, Tailwind, Storybook, and shadcn evidence. A controlled benchmark must show
more appropriate reuse without increasing inappropriate reuse. Context size and every test input are
recorded with the result.
