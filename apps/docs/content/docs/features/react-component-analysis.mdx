## What it reads

`analyzeReact` accepts source text that the analyzer has already read through `RepositoryRoot`. The
adapter never opens consumer paths, imports consumer modules, loads a tsconfig file, or writes a
file. It creates a virtual filesystem containing only those supplied sources.

```ts title="Analyze already-admitted sources"
import { analyzeReact } from "@latticeos/adapter-react";

const result = analyzeReact({
  sources: [
    {
      path: "packages/ui/src/button.tsx",
      packageKey: "@acme/ui",
      content: sourceText,
    },
  ],
  compiler: {
    baseUrl: ".",
    paths: { "@acme/ui": ["packages/ui/src/index.ts"] },
  },
});
```

Every source path must already be a normalized, repository-relative path. The adapter rejects
traversal and duplicate paths before it builds its program.

For normal repository analysis, call the analyzer bridge instead:

```ts title="Analyze an admitted repository"
import { analyzeReactProject, RepositoryRoot } from "@latticeos/analyzer";

const root = await RepositoryRoot.open("/absolute/path/to/repository");
const result = await analyzeReactProject(root);
```

The bridge selects JavaScript and TypeScript source from the bounded discovery inventory, excludes
known tool configuration and `.storybook` files, assigns the nearest workspace package key, and
passes the admitted source to the adapter. It records `truncated: true` when its source limits make
the result incomplete.

## Evidence it returns

| Evidence | Supported forms | Notes |
| --- | --- | --- |
| Components | Named and default functions, named arrow functions, `memo`, and `forwardRef` wrappers | A candidate must return JSX and have a PascalCase name, apart from an anonymous default function. |
| Props | Interfaces, type aliases, intersections, inherited properties, optional properties, destructured defaults, and literal unions | A default is stored as `defaulted: true`; LatticeOS does not store the source expression or value. |
| Imports | Default, named, namespace, type-only, aliases, and TypeScript-resolved local component targets | An import remains present when it cannot resolve to an indexed component. |
| Usages | JSX tags, direct calls, statically named JSX props, and composition links | A usage inside one indexed component that targets another is composition. |
| Diagnostics | Syntax errors, unresolved prop types, JSX spreads, and import-specifier limits | Diagnostics use relative locations and do not include source excerpts. |

Each component, prop, import, and usage references an `EvidenceRecord`. The record gives a stable
ID, source location, extraction method, classification, source fingerprint, and any limitation.

## Compiler boundary

The adapter uses the public TypeScript 6.0.3 Compiler API described by ADR-0011 under `docs/adrs/`.
Its compiler host has a fixed virtual root, reads from a map of supplied source text, emits nothing,
and has no default library. Module resolution can only find an admitted virtual source.

The TypeScript version declared by a consumer is not executed or loaded. LatticeOS uses its pinned
compiler to inspect source that the analyzer already admitted.

`analyzeReactProject` reads only a root `tsconfig.json` and only its direct `compilerOptions.baseUrl`
and `compilerOptions.paths` values. It accepts standard JSON comments, rejects traversal and
absolute alias targets, and ignores `extends` instead of loading another file. Package-specific
projects, inherited settings, and other compiler options remain unsupported in this bridge.

| Bridge bound | Default | Result when reached |
| --- | ---: | --- |
| React source files | 5,000 | Stop source selection and record `REACT_SOURCE_FILE_LIMIT` |
| Total admitted source | 20 MiB | Stop source selection and record `REACT_SOURCE_BYTES_LIMIT` |
| One React source file | 1 MiB | Skip the source and record `REACT_SOURCE_UNREADABLE` |
| Project diagnostics | 100 | Keep a bounded `REACT_PROJECT_DIAGNOSTIC_LIMIT` record |

## Limits

- Only direct component declarations are indexed. A barrel file can help resolve an import, but it
  does not create another component identity for the same declaration.
- `memo` and `forwardRef` are the supported wrappers. Other wrapper calls are not treated as
  components.
- JSX spreads are not expanded. The usage keeps any statically named props and records
  `REACT_JSX_SPREAD_PROPS`.
- If a prop type cannot resolve, LatticeOS records `unknown` with
  `REACT_PROP_TYPE_UNRESOLVED`. It does not guess.
- The adapter receives only bounded source text. `RepositoryRoot` owns filesystem limits and
  exclusions.
