<Callout title="Status" type="warning">
  The protocol, three pre-registered tasks, and local validator are implemented. No qualified agent
  result exists, so Phase 1 Reuse has not passed its benchmark gate.
</Callout>

The benchmark asks one narrow question: when an agent has LatticeOS Reuse context, does it use more
of the canonical UI already in the repository without choosing those components in the wrong place?
It does not measure Figma fidelity, browser output, semantic product judgment, or later phases.

## Matched conditions

Every task runs as a pair in fresh copies of the same controlled Next.js fixture.

| Condition | Agent receives |
| --- | --- |
| Control | The pre-registered task, fixture instructions, and permitted submission path. No LatticeOS command or output. |
| Treatment | The same material plus the exact saved JSON from `lattice context <task> --json`. |

The pair uses the same declared agent build and configuration. Its condition order is randomized and
recorded. Each condition stays inside its permitted source path.

## What a qualified result records

A result includes the task ID, fixture revision/hash, agent/config label, prompts, treatment context,
source diff or file hashes, test outcome, correction turns, duplicate components, raw Tailwind added,
and reviewer annotations.

An annotation is required before reuse counts toward the result. It names an expected canonical
component, its location in the submission, whether that use is appropriate or inappropriate, and the
reviewer's reason. LatticeOS does not use its ranking score to make that judgment.

## Gate

`reuse-v1` requires at least three qualified pairs for each pre-registered task. Treatment must have
more appropriate canonical reuse in total and no more inappropriate canonical reuse in total. Missing,
failed, out-of-scope, or unreviewed runs are reported but cannot make the gate pass.

The protocol is local and developer-only. The harness reads static records and submission text. It
does not execute application code or configuration, call a network service, collect personal data,
or publish a package.

## Run the verifier

```bash title="Verify protocol and synthetic cases"
pnpm test:benchmark
```

The test suite validates the three committed task manifests, a synthetic verifier record, insufficient
paired evidence, the positive metric rule, an inappropriate-reuse regression, changed context, control
leakage, symlinks, annotation locations, and deterministic output. Synthetic records can never satisfy
the release gate.

```bash title="Evaluate recorded trials"
pnpm benchmark:check
```

Before `benchmarks/reuse-v1/results/results.json` contains qualified trials, this command writes an
`insufficient` JSON summary and exits with status 1. Do not change that result to green without
recorded trials.

See [ADR-0017](https://github.com/Karthick-Ramachandran/LatticeOS/blob/main/docs/adrs/ADR-0017-reproducible-phase-1-reuse-benchmark-protocol.md)
and [F-003 delivery memory](https://github.com/Karthick-Ramachandran/LatticeOS/tree/main/docs/40-features/F-003-phase-1-reuse-benchmark)
for the full contract.
