## What it does

Project discovery establishes the boundary that every source adapter must use. It validates one
repository root, walks a bounded file inventory, identifies workspace packages, and records static
evidence for React, Next.js, TypeScript, Tailwind, shadcn, and Storybook.

```ts title="Detect a repository"
import { detectProject, RepositoryRoot } from "@latticeos/analyzer";

const root = await RepositoryRoot.open("/absolute/path/to/repository");
const discovery = await detectProject(root);
```

The returned paths are relative to the selected root and use forward slashes. Evidence includes the
marker location, extraction method, fingerprint, and classification. Source and configuration are
never imported or evaluated.

## Read boundary

`RepositoryRoot.readText` accepts a normalized relative path. It resolves the real target, rejects a
target outside the root, opens the final file without following a new final symlink, checks that it
is a regular file, and enforces the byte limit before and after the read.

Explicit reads may follow a symlink when its resolved target remains inside the repository.
Discovery does not follow any symlink. It records a bounded diagnostic for an internal, broken, or
escaping link.

Default exclusions include:

- `.git`, other VCS state, and `node_modules`;
- `.next`, build output, distribution output, and coverage;
- `.lattice/cache` and `.lattice/reports`; committed `.lattice` configuration remains readable;
- `.env` variants and common credential files such as `.npmrc` and `.netrc`.

Application files are read-only in Phase 1.

## Bounds

| Bound | Default | Result when reached |
| --- | ---: | --- |
| File bytes | 1,048,576 | Skip the file and report `FILE_SIZE_LIMIT` |
| Files visited | 20,000 | Stop the walk and report `FILE_COUNT_LIMIT` |
| Directory depth | 20 | Skip the deeper directory and report `DEPTH_LIMIT` |
| Entries in one directory | 20,000 | Skip that directory and report `DIRECTORY_ENTRY_LIMIT` |

Configured bounds also have hard ceilings: 16 MiB per read, 100,000 files, depth 100, and 100,000
entries in one directory. A file that grows during a read cannot make LatticeOS allocate past the
configured byte limit.

Skipped symlinks, unreadable paths, oversized files, depth limits, file limits, and malformed
manifests make incomplete negative detections `unknown`. LatticeOS uses `absent` only when the
bounded scan completed and found no supported marker.

## Workspace and tool evidence

The current workspace detector supports package globs from a root `package.json` workspaces array,
the `workspaces.packages` form, and simple list entries in `pnpm-workspace.yaml`. It maps a valid root
manifest to package key `root`. Nested packages use their package name or repository-relative path.
A duplicate name gets a path suffix and a diagnostic instead of an unstable collision.

Tool status uses package dependencies and static marker files:

| Tool | Supported markers |
| --- | --- |
| React | A `react` dependency in a detected package |
| Next.js | A `next` dependency or `next.config` file |
| TypeScript | A `typescript` dependency or `tsconfig` file |
| Tailwind | A `tailwindcss` dependency, `tailwind.config` file, or CSS `@theme` block |
| shadcn | A parseable `components.json` with a shadcn schema or supported style and alias fields |
| Storybook | A Storybook dependency or `.storybook/main` or `.storybook/preview` file |

This proves presence, not compatibility with every syntax those tools support. Source-specific
adapters provide that proof later.

## Test evidence

The named `fixtures/next-workspace` repository contains three package boundaries and all six tool
markers. Its Next.js and Storybook configuration throws immediately if executed. Detection succeeds,
which proves this path reads those files only as text.

The golden snapshot lives outside the consumer root at
`fixtures/goldens/project-discovery.next-workspace.golden.json`. Security tests cover traversal,
escaping and internal symlinks, excluded secret and generated paths, byte and depth limits, malformed
manifests, relative diagnostics, and unknown status after incomplete scans.
