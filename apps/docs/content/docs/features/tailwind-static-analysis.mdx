## What it reads

The adapter accepts caller-supplied, repository-relative text. It does not open files, import a
Tailwind configuration, run a plugin, or write output.

```ts title="Analyze admitted Tailwind inputs"
import { analyzeTailwind } from "@latticeos/adapter-tailwind";

const result = analyzeTailwind({
  repeatedBundleThreshold: 2,
  sources: [
    { path: "app/globals.css", kind: "css", content: cssText },
    { path: "tailwind.config.ts", kind: "config", content: configText },
    { path: "components/card.tsx", kind: "source", content: sourceText },
  ],
});
```

Paths must already be normalized and unique. Direct callers own their own admission controls.

## Repository bridge

Call `analyzeTailwindProject` when analysis starts from a repository root. It calls
`detectProject`, then admits only repository-relative Tailwind configuration files, CSS files, and
supported JavaScript or TypeScript source files through `RepositoryRoot`. It never imports a
consumer config.

```ts title="Analyze a repository safely"
import { analyzeTailwindProject, RepositoryRoot } from "@latticeos/analyzer";

const root = await RepositoryRoot.open("/workspace/product");
const result = await analyzeTailwindProject(root, {
  maxTailwindSourceFiles: 5_000,
  maxTailwindSourceBytes: 20 * 1024 * 1024,
});
```

The bridge skips Tailwind source admission when project detection is confidently `absent`. If the
scan is incomplete or a limit is reached, `truncated` is true and a diagnostic explains which
evidence may be missing. Default bounds are 5,000 files, 20 MiB total input, 1 MiB per file, and
100 diagnostics. Hard limits are 20,000 files, 64 MiB, 16 MiB per file, and 1,000 diagnostics.

## Supported evidence

| Input | Supported form | Result |
| --- | --- | --- |
| Tailwind v4 CSS | Custom properties inside `@theme { ... }` | Tokens such as `--color-brand` with their CSS values |
| Tailwind v3 configuration text | Direct `theme` and `theme.extend` object values that are static strings or numbers | Tokens such as `colors.accent` and `spacing.card` |
| JSX and TSX source | Quoted `className` values, brace-wrapped static strings, and fully static `cn`, `clsx`, or `classnames` calls | Exact repeated class-bundle evidence |

Class literals use the `static-source` method from ADR-0012. It means a deterministic text scanner
matched a literal in admitted source. It does not mean LatticeOS evaluated an expression or inferred
component meaning.

## Repeated bundles

The adapter splits a static class string on whitespace and sorts tokens for comparison. A bundle
appears only when its occurrence count meets `repeatedBundleThreshold`, which defaults to 2.

The index follows ADR-0013 and keeps both views:

- `classes` is the normalized token sequence used for grouping.
- `originals` contains the source literal for every occurrence, in the same order as `locations`.

For example, `"rounded-lg border p-4"` and `"border p-4 rounded-lg"` produce one repeated bundle,
but inspect output retains both spellings and their source locations. This is repetition evidence,
not a request to create a component.

## Limits

- Config parsing reads only direct object literals below `theme`. It does not load imports, execute
  code, resolve variables, arrays, function calls, or plugins.
- Source scanning ignores matches inside ordinary strings and comments. It supports the literal forms
  listed above, not arbitrary JavaScript or JSX expressions.
- A no-substitution template string is static. Any interpolation is dynamic.
- A merge call is indexed only if every top-level argument is a static string. Mixed calls report a
  diagnostic and do not invent a complete bundle.
- Bare `cn`, `clsx`, and `classnames` calls are matched by name without import resolution. Their
  source evidence is marked heuristic and says why.
- Dynamic `className` expressions and dynamic config values are reported without copying those values
  into evidence.

## Test evidence

The named `fixtures/next-workspace` fixture contains a v4 CSS theme, a Tailwind configuration that
throws if executed, repeated class attributes with different token order, and a fully static `cn`
call. The direct adapter and repository bridge goldens are
`fixtures/goldens/tailwind-analysis.next-workspace.golden.json` and
`fixtures/goldens/tailwind-project.next-workspace.golden.json`.

Run `pnpm --filter @latticeos/adapter-tailwind golden:update` and
`pnpm --filter @latticeos/analyzer golden:update` to regenerate the snapshots, inspect each diff,
then run the matching package tests.
