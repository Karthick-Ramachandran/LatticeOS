<Callout title="Implemented" type="info">
  The analyzer can now save a validated Reuse index to the one generated path that ADR-0004 permits:
  `.lattice/cache/reuse-index.json`. Public CLI refresh behavior is still separate work.
</Callout>

## Use it

```ts title="Read or refresh generated state"
import { analyzeProject, readReuseIndex, RepositoryRoot, writeReuseIndex } from "@latticeos/analyzer";

const root = await RepositoryRoot.open("/workspace/product");
const cached = await readReuseIndex(root);
const index = cached.status === "hit"
  ? cached.index
  : (await analyzeProject(root, { generatorVersion: "0.0.0" })).index;

if (cached.status !== "hit") await writeReuseIndex(root, index);
```

`readReuseIndex` returns one of three states:

| Status | Meaning | Caller action |
| --- | --- | --- |
| `hit` | The JSON parses and satisfies the current core schema. | Use `index`. |
| `missing` | No generated cache exists. | Analyze and save a new index. |
| `invalid` | The file is malformed, oversized, or incompatible. | Analyze and replace it. |

The cache is derived state, never accepted product knowledge. Invalid data is not returned to a
caller as evidence. An unsafe cache path, such as a symlink or an escaping directory, is an error,
not an ordinary `invalid` result.

## Write boundary

`writeReuseIndex` validates and deterministically serializes the core index before asking
`RepositoryRoot` to replace the exact cache target. The root authority creates only `.lattice` and
`.lattice/cache` regular directories, writes a unique sibling temporary file with owner-only mode,
syncs it, and renames it over the generated cache file.

The API has no output-path argument. It cannot write application source, reports, arbitrary files,
or a path outside the selected repository. It rejects symlinked cache directories and final cache
files. Cache reads are bounded to 16 MiB and reject symlinks, non-regular files, and paths outside
the selected root.

The regular `readText` API continues to exclude generated cache paths. Only the dedicated cache
methods can access this one LatticeOS-owned file. A cache miss does not create `.lattice` directories;
only a successful cache write creates the owned directory path.

## Limits and residual risk

An index larger than 16 MiB is rejected rather than partially written or read. A later scale change
needs an ADR and a fixture before raising that ceiling.

The final file open uses `O_NOFOLLOW` where the platform supports it. As with every local filesystem
operation, a hostile concurrent replacement of an already checked ancestor directory is a residual
race. Packed cross-platform tests remain required before release.

## Test evidence

Analyzer tests prove cache misses, valid hits, malformed and incompatible state, atomic replacement,
application-source preservation, final-file symlinks, and symlinked `.lattice` directories. Run:

```bash
pnpm --filter @latticeos/analyzer test
```
