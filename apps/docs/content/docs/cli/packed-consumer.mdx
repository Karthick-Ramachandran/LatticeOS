---
title: Packed consumer proof
description: Verify the packaged lattice binary against the controlled Next.js fixture.
---

The package gate proves the artifact that would be installed, not a workspace-linked development
copy. It does not publish LatticeOS. The public package remains pre-release until the Phase 1
benchmark and final review pass.

Run the proof from the repository root:

```bash title="Run the packed consumer gate"
pnpm test:package
```

## What the gate checks

The CLI package builds its seven required LatticeOS packages, then packs each one into a tarball. A
temporary copy of `fixtures/next-workspace` installs those local tarballs with npm. Install scripts
are disabled. The test restores the fixture's workspace declaration before analysis, so `lattice`
sees the same React, Next.js, Tailwind, shadcn, and Storybook markers that the fixture commits.

The test then proves all of these facts:

- npm extracted `@latticeos/cli` outside this worktree and exposed the `lattice` binary.
- `lattice --help` runs from the installed package.
- `lattice search Button --json` runs inside the copied fixture and returns `Button`.
- The command creates `.lattice/cache/reuse-index.json` with schema version 1.
- `packages/ui/src/button.tsx` has identical contents before and after analysis.
- The temporary tarballs and consumer directory are removed when the test ends.

The test does not start Next.js, build the fixture application, publish to npm, or execute fixture
source or configuration. It is a package and analysis proof, not an application-runtime test.

## Why the temporary workspace change exists

The fixture contains `workspace:*` dependencies that npm cannot install directly in this controlled
tarball setup. The gate removes only the root `workspaces` field in its temporary copy for `npm
install --workspaces=false`, then restores that field before it invokes `lattice`. The committed
fixture and its workspace detection behavior remain unchanged.

## Security boundary

The test script has fixed package directories and uses a temporary directory it created itself. It
does not accept a consumer-supplied package path. Package installation uses local LatticeOS tarballs,
disables lifecycle scripts, and omits fixture development dependencies. A package manager can still
contact its registry to resolve the existing pinned TypeScript dependency during this developer test;
the shipped `lattice` runtime has no network path.

## Test evidence

`packages/cli/scripts/test-packed-consumer.mjs` is the implementation. The package gate builds
dependencies first, then runs that script. It has passed against the controlled Next.js workspace
fixture with the installed binary, help command, real search command, generated-cache check, and
source-preservation assertion.
