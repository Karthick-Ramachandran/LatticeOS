LatticeOS is a repository-native UI control plane for coding agents. It is designed to help agents
understand a product's UI, work within accepted rules, and check whether code still matches intent.

It works with the frontend stack already in the repository. It is not a UI kit, CSS framework,
component generator, or replacement design system.

<Callout title="Current build" type="info">
  Phase 1 Reuse is in progress. It starts with evidence about existing React components, real usage
  sites, props, stories, installed registry components, and repeated Tailwind structures. Figma and
  visual convergence stay out of the build until Reuse passes its benchmark.
</Callout>

## What good evidence looks like

A result should tell you which component it found, where it is exported, which props are documented
by source, where the repository already uses it, and why it ranked for the task. If analysis cannot
prove a fact, the output labels the limit instead of filling the gap with a guess.

This structure is deliberate. Storybook asks agents to verify documented props and stories before
using a component. Figma Code Connect links design components to real code paths and usage guidance.
shadcn registries expose concrete component records. Next.js ships version-matched docs for agents.
LatticeOS applies the same evidence-first idea to the repository as a whole.
